# Админка «Товар в деле»

`https://tovarvdele.ru/admin/` — правки сайта без программиста. Разделы: **Калькулятор** (цены, приёмка, скидка,
хранение, операции: добавить, удалить, переставить), **Контакты** (телефон, Telegram, адрес на всех страницах),
**Тексты и вопросы** (заголовки блоков главной и FAQ), **SEO** (title, description, og:title страниц),
**История** (предыдущие версии правок и «вернуть весь сайт как в вёрстке»). В каждом разделе есть «Вернуть как в вёрстке».

Чистый PHP 8.1+ без composer, базы и сборки. Подходит для Host-0 рег.ру (Apache + .htaccess, PHP 8.3 на сайте, 8.2 в SSH).
Посетители по-прежнему получают статические HTML-файлы, PHP работает только в `/admin/`.

## Как это устроено
- Файлы из git (`index.html`, `kontakty/`, `dokumenty/`, `llms.txt`) — **вёрстка**. Админка хранит их копию у себя и
  отдельно — свои **правки** (`settings.json`: только то, что отличается от вёрстки).
- При сохранении админка пишет на сайт «вёрстка + правки» (атомарно, через временный файл).
- «Вернуть как в вёрстке» просто убирает правки раздела и снова пишет файлы: получается вёрстка байт в байт.
- Что именно можно менять, размечено в вёрстке главной: `const CALC_CFG={…}` (калькулятор), `const FAQ=[…]`,
  `<!--t:ключ-->…<!--/t-->` (тексты блоков), `<span class="cfg-disc|cfg-rate|cfg-free">` (цифры в текстах).
  Контакты берутся из `data/seo.json` (`organization.phone`, `organization.address.street`) и ссылки `https://t.me/…` на главной.

## Где лежат данные (вне сайта)
`<домашняя папка>/.tovarvdele-admin/` — на Host-0 это `/var/www/<логин>/data/.tovarvdele-admin/` (на два уровня
выше `www/tovarvdele.ru`). Внутри: `users.json` (логины и password_hash), `settings.json` (правки), `templates/`
(копия вёрстки), `history/` (50 предыдущих версий правок), `sessions/`, `throttle.json` (лимит входа), `audit.log`.
Другое место — в `admin/config.local.php` (пример в `config.sample.php`, файл не в git) или переменной `TVD_ADMIN_DATA`.
Если папка данных оказалась внутри сайта, админка не запустится.

## Установка
1. Залить репозиторий в `www/tovarvdele.ru/` как обычно (вместе с `.htaccess` в корне и в `admin/`).
2. Создать админа по SSH (пароль в git не попадает, не короче 12 знаков):
   ```
   cd www/tovarvdele.ru
   php admin/bin/create-admin.php vitalii            # спросит пароль; повторно — смена пароля
   php admin/bin/create-admin.php vitalii --delete   # удалить
   ```
3. Открыть https://tovarvdele.ru/admin/ и проверить, что закрыто (должно быть 403 или 404):
   `/admin/lib/site.php`, `/admin/bin/create-admin.php`, `/admin/README.md`, `/data/seo.json`, `/tools/seo.py`.

Защита: password_hash, сессия в своей папке (HttpOnly, SameSite=Strict, Secure на https, 4 часа без действий),
CSRF-токен и проверка Origin на каждом POST, 5 неудачных входов с адреса (или 10 на логин) — пауза 15 минут,
CSP и запрет фреймов, noindex.

## Выкладка из git и правки админки
Правки из админки живут в папке данных, а не в git, поэтому **выкладка их не теряет**, но перезаписывает файлы на сайте
вёрсткой без правок. Порядок после каждой выкладки:

1. Залить файлы по SFTP как обычно.
2. Применить правки к новой вёрстке — одно из двух:
   - по SSH: `php admin/bin/apply.php` (`--check` — только показать, что не совпадает);
   - или открыть `/admin/`: админка сама заметит новую вёрстку и покажет жёлтую плашку с кнопкой «Применить правки».

Если в новой вёрстке поменялось то, что правили в админке (например, цена), на сайте останется значение из админки.
Чтобы взять значение из вёрстки, нажмите «Вернуть как в вёрстке» в этом разделе.

Не правьте по SFTP файлы, которыми управляет админка, руками: админка примет такой файл за новую вёрстку.

## Генераторы и SEO
`tools/seo.py`, `tools/contacts_page.py`, `tools/legal_pages.py` работают с вёрсткой в git как раньше. Разметку
калькулятора, FAQ и текстов на главной они сохраняют.

## Проверки
```
php admin/tests/run.php
```
Копирует сайт во временную папку и проверяет все разделы, откат байт в байт, выкладку новой вёрстки поверх правок,
вход, CSRF, лимит попыток и закрытость служебных файлов (через встроенный сервер PHP).
